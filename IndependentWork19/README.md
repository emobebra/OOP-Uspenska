## Висновок

у цій самостійній роботі я навчилася створювати власні винятки та використовувати бібліотеку Polly для обробки збоїв. реалізувала три стратегії: Retry, Circuit Breaker і Timeout. Polly спрощує підвищення відмовостійкості програми, але неправильне налаштування повторних спроб і затримок може створювати додаткове навантаження або передчасно скасовувати операції

## Контрольні запитання

**1. Поясніть різницю між підходами “кидати виняток” та “повертати Result”. Наведіть приклад
для кожного.**

виняток використовують для непередбачених помилок, наприклад втрати підключення до сервера. Result повертає результат операції без винятку, наприклад повідомлення про неправильне введення даних

**2. Які три стандартні конструктори рекомендується реалізовувати у власному типі винятку?**

конструктор без параметрів, конструктор із повідомленням message та конструктор із message і innerException

**3. Чим Circuit Breaker відрізняється від Retry? Коли який патерн доцільніший?**

Retry повторює операцію після тимчасової помилки, а Circuit Breaker блокує запити до несправного сервісу. Retry краще використовувати при короткочасних збоях, а Circuit Breaker при тривалій недоступності сервісу

**4. Для чого потрібен Bulkhead i яку проблему він вирішує?**

Bulkhead обмежує використання ресурсів окремими операціями, щоб перевантаження одного сервісу не впливало на роботу інших частин програми

**5. Чому Jitter важливий при реалізації Retry з експоненційною затримкою?**

Jitter додає випадкову затримку між повторними спробами, щоб багато запитів не виконувалися одночасно та не перевантажували сервер

**6. Які ризики виникають при застосуванні Retry до неідемпотентної операції?**

повторне виконання може спричинити дублювання дій, наприклад повторне списання грошей або створення однакових записів у базі даних
