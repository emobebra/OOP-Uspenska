## 1. Аналіз використання колекцій у відкритих проєктах

### Приклад 1. Dictionary у .NET Runtime

У бібліотеці System.Linq метод `ToDictionary()` використовується для перетворення послідовності елементів у словник. Кожен елемент зберігається за унікальним ключем, що дозволяє швидко знаходити потрібні дані.

Dictionary зручніший за List, коли необхідно здійснювати пошук за ключем без послідовного перебору елементів. Середня складність додавання та пошуку становить O(1), у найгіршому випадку — O(n).

Особливістю є можливість використання `IEqualityComparer<TKey>` для визначення правил порівняння ключів. Якщо в початковій колекції є однакові ключі, метод `ToDictionary()` генерує виняток.

**Джерело:** [ToCollection.cs — .NET Runtime](https://github.com/dotnet/runtime/blob/main/src/libraries/System.Linq/src/System/Linq/ToCollection.cs)

### Приклад 2. HashSet у .NET Runtime

У бібліотеці System.Linq метод `ToHashSet()` створює множину унікальних елементів із початкової колекції. Повторювані значення автоматично виключаються.

HashSet доцільно використовувати замість List, коли потрібно уникнути дублікатів і швидко перевіряти наявність елементів. Середня складність додавання та пошуку становить O(1), у найгіршому випадку — O(n).

Метод підтримує передачу власного `IEqualityComparer<T>`, що дозволяє змінювати правила порівняння елементів, наприклад не враховувати регістр літер.

**Джерело:** [ToCollection.cs — .NET Runtime](https://github.com/dotnet/runtime/blob/main/src/libraries/System.Linq/src/System/Linq/ToCollection.cs)

### Приклад 3. Dictionary і HashSet разом у Microsoft VSTest

У відкритому проєкті Microsoft VSTest, який використовується для тестування .NET-застосунків, у класі `DiscoveryCompleteEventArgs` застосовується `Dictionary<string, HashSet<string>>` для зберігання інформації про знайдені розширення тестової платформи.

Dictionary пов'язує рядковий ключ із набором розширень, а HashSet забезпечує унікальність значень у кожному наборі.

Таке поєднання зручніше за звичайні списки, оскільки дозволяє швидко знаходити потрібну групу та перевіряти наявність елементів. Середня складність цих операцій становить O(1).

Для порівняння рядків за потреби можна використовувати `StringComparer`, однак у наведеному оголошенні колекції спеціальний comparer не задано.

**Джерело:** [DiscoveryCompleteEventArgs.cs — Microsoft VSTest](https://github.com/microsoft/vstest/blob/main/src/Microsoft.TestPlatform.ObjectModel/Client/Events/DiscoveryCompleteEventArgs.cs)

## 2. Практична реалізація

### Сценарій 1. FileMetadataCache

Я реалізувала клас `FileMetadataCache` для кешування метаданих файлів за допомогою `Dictionary<string, FileMetadata>`

У класі реалізовано методи `Add()`, `Get()`, `Remove()` та `Contains()`, які дозволяють додавати інформацію про файли, отримувати її за ключем, видаляти записи та перевіряти їх наявність

Програма демонструє збереження назви файлу, його розміру, дати останньої зміни та хешу. Після видалення запису перевірка підтверджує його відсутність у кеші

### Сценарій 2. TagManager

Я реалізувала клас `TagManager` для керування унікальними тегами статей за допомогою `Dictionary<string, HashSet<string>>`.

Методи `AddTag()` і `RemoveTag()` забезпечують додавання та видалення тегів. Метод `GetAllUniqueTags()` отримує всі унікальні теги, а `FindCommonTags()` визначає спільні теги двох статей

У програмі використано операції `UnionWith()`, `IntersectWith()` та `ExceptWith()` для об'єднання, перетину й різниці множин. Для порівняння тегів без урахування регістру застосовано `StringComparer.OrdinalIgnoreCase`

### Сценарій 3. SearchIndex (додатковий)

Додатковий сценарій передбачає створення пошукового індексу на основі `Dictionary<string, HashSet<int>>`.

У такій структурі кожному слову відповідає множина ідентифікаторів документів, у яких воно зустрічається. Це дозволяє швидко знаходити документи за окремим словом, а також виконувати пошук за декількома словами через перетин множин

## 3. Порівняльна таблиця складності операцій

| Операція | List<T> | Dictionary<TKey, TValue> | HashSet<T> |
|---|---|---|---|
| Додавання | O(1)* | O(1)* | O(1)* |
| Пошук за значенням | O(n) | O(n) | O(1) |
| Пошук за ключем | Немає | O(1) | Немає |
| Видалення | O(n) | O(1) | O(1) |
| Перевірка наявності | O(n) | O(1) за ключем | O(1) |

## 4. Висновки про вибір колекцій

**Коли Dictionary краще за List?**

Dictionary доцільно використовувати, коли потрібно зберігати пари ключ–значення та швидко знаходити дані за унікальним ключем. Наприклад, для кешування інформації про файли або пошуку користувачів за ідентифікатором

**Коли HashSet є оптимальним вибором?**

HashSet найкраще підходить для зберігання унікальних значень, перевірки їх наявності та виконання операцій над множинами. Наприклад, для системи тегів або видалення повторюваних елементів

**Які особливості потрібно враховувати?**

Dictionary не допускає дублювання ключів, а HashSet зберігає лише унікальні значення. Для коректної роботи важливо правильно визначати рівність елементів та їхні хеш-коди. Також ці колекції не гарантують порядок елементів

## 5. Загальний висновок

Під час самостійної роботи я дослідила застосування колекцій Dictionary та HashSet у відкритих проєктах .NET Runtime і Microsoft VSTest

У практичній частині реалізувала кеш метаданих файлів та систему унікальних тегів. З'ясувала, що Dictionary забезпечує ефективний пошук за ключем, а HashSet дозволяє працювати з унікальними значеннями та виконувати операції над множинами

Використання цих колекцій спрощує організацію даних і дозволяє підвищити ефективність програм
