## 1. Аналіз використання колекцій у Newtonsoft.Json

для дослідження я обрала відкриту бібліотеку Newtonsoft.Json, яка призначена для серіалізації та десеріалізації JSON у .NET. у її вихідному коді знайшла приклади практичного застосування dictionary та hashset

### Приклад 1. Dictionary<TKey, TValue>

**Файл:** "XmlNodeConverter.cs", метод "SerializeGroupedNodes()".

У цьому методі використовується "Dictionary<string, object>" для групування xml-вузлів за назвами під час перетворення xml у json

nodesGroupedByName = new Dictionary<string, object>();

Dictionary обрано через можливість швидкого пошуку вузлів за назвою. На відміну від List, немає потреби перебирати всі елементи. Середня складність додавання та пошуку становить O(1), найгірша — O(n). Використовується стандартне порівняння рядкових ключів

[Джерело — XmlNodeConverter.cs](https://github.com/JamesNK/Newtonsoft.Json/blob/master/Src/Newtonsoft.Json/Converters/XmlNodeConverter.cs)

### Приклад 2. HashSet<T>

**Файл:** `JContainer.cs`, метод `MergeEnumerableContent()`.

У цьому методі використовується `HashSet<JToken>` для об'єднання JSON-масивів без повторення однакових елементів

HashSet<JToken> items = new HashSet<JToken>(target, EqualityComparer);

HashSet обрано для автоматичного усунення дублікатів і швидкої перевірки наявності значень. Середня складність додавання та пошуку становить O(1), найгірша — O(n). Особливістю є використання спеціального `EqualityComparer` для порівняння JSON-токенів за вмістом. Цей варіант реалізації використовується за умови компіляції `HAVE_HASH_SET`

[Джерело — JContainer.cs](https://github.com/JamesNK/Newtonsoft.Json/blob/master/Src/Newtonsoft.Json/Linq/JContainer.cs)

## 2. Порівняльна таблиця колекцій

| Операція | List<T> | Dictionary<TKey, TValue> | HashSet<T> |
|---|---|---|---|
| Додавання | O(1)* | O(1)* | O(1)* |
| Пошук за значенням | O(n) | O(n) | O(1) |
| Пошук за ключем | N/A | O(1) | N/A |
| Видалення | O(n) | O(1) | O(1) |
| Перевірка наявності | O(n) | O(1) за ключем | O(1) |


## 3. Висновки про вибір колекцій

**Коли Dictionary краще за List?**

dictionary краще використовувати, коли потрібно швидко знаходити дані за унікальним ключем, наприклад для кешування файлів або пошуку користувачів за ідентифікатором

**Коли HashSet є оптимальним вибором?**

hashset підходить для зберігання унікальних значень, видалення дублікатів і виконання операцій об'єднання, перетину та різниці множин

**Які підводні камені при використанні?**

dictionary не допускає однакових ключів, а HashSet дублікатів значень. Обидві колекції залежать від правильного порівняння елементів і обчислення хеш-кодів. Вони не гарантують порядок елементів і можуть потребувати більше пам'яті, ніж list

## 4. Приклади з власного коду

### Сценарій 1. FileMetadataCache

Я реалізувала кеш метаданих файлів за допомогою `Dictionary<string, FileMetadata>`.

Метод `Add()` додає інформацію про файл, `Get()` отримує її за ключем, `Remove()` видаляє запис, а `Contains()` перевіряє його наявність.

Під час демонстрації програма виводить назву `document.txt`, розмір 1024 байти, дату зміни та хеш, після чого видаляє запис із кешу.

### Сценарій 2. TagManager

Я реалізувала систему тегів статей на основі `Dictionary<string, HashSet<string>>`.

Методи `AddTag()` і `RemoveTag()` відповідають за додавання та видалення тегів. `GetAllUniqueTags()` використовує `UnionWith()`, `FindCommonTags()` — `IntersectWith()`, а `FindDifferentTags()` — `ExceptWith()`.

Програма знаходить спільні теги `CSharp` та `OOP` і відмінний тег `DotNet`. Для уникнення дублікатів через регістр літер використано `StringComparer.OrdinalIgnoreCase`.

## 5. Загальний висновок

Під час самостійної роботи я дослідила використання Dictionary та HashSet у бібліотеці Newtonsoft.Json і реалізувала два практичні сценарії мовою C#.

З'ясувала, що Dictionary доцільно використовувати для швидкого пошуку за ключем, а HashSet — для зберігання унікальних значень і виконання операцій над множинами. Правильний вибір колекції дозволяє зробити програму ефективнішою.
