## Короткий опис структури

у роботі реалізовано два проєкти: консольний lab7v3 і тестовий lab7v3.Tests на xUnit. у lab7v3 інтерфейс IEntity містить єдину властивість int Id, а клас сутності Order за варіантом 3 реалізує його і має поля OrderDate (DateTime), TotalAmount (decimal) та CustomerId (int). узагальнений інтерфейс IRepository<T> з обмеженням where T : IEntity описує методи GetById, GetAll, Add, Update і Delete. клас InMemoryRepository<T> реалізує його і зберігає елементи в List<T>. якщо елемент із потрібним Id не знайдено, GetById, Update і Delete кидають KeyNotFoundException, а Add кидає ArgumentException при дублікаті Id та ArgumentNullException для null. GetAll повертає копію списку, щоб зовні не можна було змінити внутрішній список. у Main створюється InMemoryRepository<Order>, додаються три замовлення, потім одне отримується за Id, оновлюється й видаляється, а результати виводяться в консоль. у lab7v3.Tests написано 11 тестів, які покривають усі п'ять методів, включно з неіснуючими Id, дублікатом і null, і всі вони проходять

## Контрольні запитання

**1. Яка роль where-обмежень у Generics? Наведіть приклади їх використання.**

where-обмеження кажуть компілятору, які типи можна підставляти замість T, і завдяки цьому в узагальненому коді можна користуватись можливостями цього типу. у моїй роботі стоїть where T : IEntity, тому всередині репозиторію можна писати item.Id. інші приклади: where T : class, where T : struct, where T : new()

**2. Навіщо потрібен шаблон IRepository? Які переваги він дає?**

він відокремлює роботу з даними від решти програми, яка працює лише з інтерфейсом і не знає, де зберігаються дані. тому InMemoryRepository можна замінити на реалізацію для бази без переписування решти коду, а один IRepository<T> підходить для всіх сутностей

**3. Поясніть, чому юніт-тести є важливими при розробці узагальнених компонентів.**

узагальнений код працює з багатьма типами, тому помилка в ньому зачепить усіх. тести одразу показують, що логіка працює, і перевіряють крайні випадки, як-от неіснуючий Id або дублікат

**4. Які проблеми вирішують Generics порівняно з використанням object?**

з object типи перевіряються тільки під час виконання (InvalidCastException), потрібні явні приведення, а значущі типи упаковуються (boxing). Generics дають перевірку типів на етапі компіляції без приведень і boxing, і не треба писати окремий клас для кожного типу
