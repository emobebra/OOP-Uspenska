# Звіт до самостійної роботи №10

**Тема:** Колекції в практиці ООП: інвертований індекс і вимірювання продуктивності.

## Опис реалізації

У програмі реалізовано пошук документів за ключовими словами. Клас `Document` містить ID, назву й текст документа. У класі `InvertedIndex` словник `Dictionary<string, HashSet<int>>` зберігає для кожного слова множину ID документів, у яких воно є.

Метод `SearchSingleWord` знаходить документи за одним словом. `SearchMultipleWords` використовує `IntersectWith` для пошуку документів, які містять усі задані слова (AND). `SearchAnyWord` використовує `UnionWith`, щоб знайти документи з будь-яким із заданих слів (OR).

`TextProcessor` переводить текст у нижній регістр і розбиває на слова, прибираючи розділові знаки. Для звичайного пошуку та пошуку через індекс застосовується однакова обробка тексту. Символ `#` зберігається в позначенні мови C#.

## Порівняння продуктивності

Програма порівнює лінійний пошук і пошук через індекс на 10, 100, 1000 і 10000 документах. Для кожного обсягу пошук виконується 20 разів, а в таблиці виводиться середня кількість тактів `Stopwatch`. Створення індексу відбувається окремо й не входить у час пошуку.

|---|---:|---:|---|
| 10 | ... | ... | True |
| 100 | ... | ... | True |
| 1000 | ... | ... | True |
| 10000 | ... | ... | True |

## Висновок

Я реалізувала інвертований індекс і три методи пошуку, використовуючи `Dictionary` та `HashSet`. Індекс дає змогу шукати документи за словами, не переглядаючи щоразу весь текст. Лінійний пошук не потребує попередньої побудови індексу, а індекс вигідний для багаторазових запитів, особливо коли документів багато. Конкретний поріг вигідності на моєму комп'ютері визначається таблицею вище. Час початкової побудови індексу теж потрібно враховувати, якщо пошук виконується лише один раз.

## Контрольні запитання

**1. Чому підходить Dictionary<string, HashSet<int>>?** Словник швидко знаходить слово, а HashSet зберігає унікальні ID документів.

**2. Для чого HashSet в AND/OR?** `IntersectWith` залишає спільні документи, а `UnionWith` об'єднує всі знайдені документи без повторів.

**3. Чому потрібна однакова нормалізація?** Щоб обидва способи шукали однакові слова й результати можна було правильно порівняти.

**4. Які обмеження простого індексу?** Він не враховує важливість документів, форми слів та точний порядок слів у фразі.
