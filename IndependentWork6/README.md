## Два сценарії

## сценарій перший, система сповіщень

Обраний підхід: інтерфейс INotifier.

я обрала інтерфейс, тому що email, sms і push мають спільний метод Send(), але різну реалізацію, aбстрактний клас тут менш зручний, оскільки спільної логіки немає

Реалізація:
interface INotifier
{
    void Send(string message);
}

## сценарій другий, обробка файлів

Обраний підхід: абстрактний клас FileProcessor.

я обрала абстрактний клас, тому що всі обробники мають спільні методи Open() і Close(), але по-різному реалізують Process(). інтерфейс тут менш зручний, оскільки потрібно використовувати спільний код і зберігати назву файлу

Реалізація:

public void Open()
{
    Console.WriteLine($"Відкриття файлу: {FileName}");
}

public abstract void Process();

## Відповіді на контрольні запитання

**1. Які ознаки підказують, що сценарій краще моделювати через інтерфейс?**

інтерфейс краще використовувати, коли різні класи мають спільні методи, але реалізують їх по-різному. гаприклад, email, sms і push мають метод send(), але кожен працює по-своєму

**2. У чому перевага абстрактного класу для процесів зі спільними кроками виконання?**

абстрактний клас дозволяє один раз написати спільні методи й використовувати їх у похідних класах, це зменшує повторення коду

**3. Як порівняння двох підходів допомагає прийняти архітектурне рішення?**

порівняння допомагає зрозуміти, що краще використати, а якщо потрібні лише спільні методи, то інтерфейс, а якщо є спільна логіка та властивості — абстрактний клас

**4. Яку роль у ваших прикладах відіграє поліморфізм?**

поліморфізм дозволяє працювати з різними об'єктами через один базовий тип. у моїй роботі це списки INotifier і FileProcessor, де кожен об'єкт виконує метод по-своєму. і перевизначення методів працюють правильно
