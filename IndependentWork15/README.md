## Висновок

у цій самостійній роботі я реалізувала чотири узагальнені методи для роботи з колекціями за допомогою делегатів і лямбда-виразів. Перевірила їхню роботу на трьох типах колекцій і порівняла з операторами LINQ

## Контрольні запитання

**1. Чому делегати є зручним механізмом для передавання поведінки в узагальнені методи?**

тому що дозволяють передавати різні функції в один метод без зміни його коду

**2. У чому різниця між Func<T, TResult>, Action<T> та Predicate<T>?**

func, приймає параметри та повертає результат, action, виконує дію без повернення результату, predicate, перевіряє умову та повертає true або false

**3. Які переваги дає поєднання generic-методів і лямбда-виразів під час роботи з колекціями?**

можна використовувати один метод для різних типів даних, а потрібні дії записувати коротко через лямбда-вирази

**4. У яких випадках власні утиліти на кшталт Map чи Filter корисно реалізувати самостійно,
навіть якщо існує LINQ?**

коли потрібно краще зрозуміти роботу колекцій або реалізувати власну логіку обробки даних
