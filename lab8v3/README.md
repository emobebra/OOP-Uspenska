# Лабораторна робота №8

## Варіант 3

**Виконала: Успенська Емілія**

**Тема**: Делегати й лямбда-вирази у практиці колекцій: CollectionHelper<T>.

**Мета**: Навчитися передавати поведінку як параметр через делегати Func, Action, Predicate, будувати на цій основі універсальні операції над колекціями та використовувати лямбда-вирази у практиці ООП.

## Короткий опис структури

У роботі реалізовано консольний проєкт lab8v3. Статичний узагальнений клас CollectionHelper<T> містить метод Filter(IEnumerable<T> collection, Predicate<T> predicate) за варіантом 3, який повертає нову колекцію з елементів, для яких predicate повертає true. Метод реалізовано власним циклом foreach, без LINQ-оператора Where. Якщо collection або predicate дорівнює null, кидається ArgumentNullException, а якщо жоден елемент не підходить або колекція порожня, повертається порожня колекція. Клас Product має поля Id (int), Name (string), Price (decimal) та Category (string). У Main метод Filter застосовується до трьох колекцій з лямбда-виразами: у List<int> відбираються парні числа, у List<string> рядки довші за 4 символи, у List<Product> продукти з ціною більше 100. Також показано граничні випадки (жоден елемент не підходить, порожня колекція), а результати виводяться в консоль.

## Контрольні запитання

**1. Що таке делегат і для чого він використовується?**

Делегат це тип, який зберігає посилання на метод із певною сигнатурою. Його використовують, щоб передавати поведінку як параметр: наприклад, метод Filter не знає, за якою умовою фільтрувати, і отримує її ззовні через делегат Predicate<T>.

**2. У чому полягає різниця між Func та Action?**

Func приймає параметри і повертає значення (останній тип у Func<T, TResult> це тип результату), а Action приймає параметри, але нічого не повертає (void). Predicate<T> це окремий випадок, який приймає елемент і повертає true або false.

**3. Як лямбда-вирази спрощують роботу з делегатами?**

Не потрібно писати окремий іменований метод. Умову можна записати коротко прямо у виклику, наприклад n => n % 2 == 0, і вона буде видна поруч із кодом, який її використовує.

**4. Які переваги дають узагальнені методи при роботі з колекціями?**

Код пишеться один раз і працює для будь-якого типу (int, string, Product), без дублювання. При цьому зберігається типобезпека: помилки типів знаходить компілятор, а приведення типів не потрібні. У моїй роботі CollectionHelper<T>.Filter працює і зі списком чисел, і зі списком рядків, і зі списком продуктів
