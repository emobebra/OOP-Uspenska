# Лабораторна робота №8

## Варіант 3

**Виконала: Успенська Емілія**

**Тема**: Делегати й лямбда-вирази у практиці колекцій: CollectionHelper<T>.

**Мета**: Навчитися передавати поведінку як параметр через делегати Func, Action, Predicate, будувати на цій основі універсальні операції над колекціями та використовувати лямбда-вирази у практиці ООП.

## Короткий опис структури

у роботі було реалізовано консольний проєкт лабораторна 8. статичний узагальнений клас CollectionHelper<T> містить метод Filter(IEnumerable<T> collection, Predicate<T> predicate), який повертає нову колекцію з елементів, для яких predicate повертає true. метод реалізовано власним циклом foreach, без LINQ-оператора where. якщо collection або predicate дорівнює null, кидається ArgumentNullException, або якщо жоден елемент не підходить або колекція порожня, повертається порожня колекція. клас product має поля id (int), name (string), price (decimal) та category (string). у main метод filter застосовується до трьох колекцій з лямбда-виразами: у List<int> відбираються парні числа, у List<string> рядки довші за 4 символи, у List<Product> продукти з ціною більше 100, також показано граничні випадки (жоден елемент не підходить, порожня колекція), а результати виводяться в консоль

## Контрольні запитання

**1. Що таке делегат і для чого він використовується?**

делегат це тип, який зберігає посилання на метод із певною сигнатурою, і його використовують, щоб передавати поведінку як параметр, наприклад, метод filter не знає, за якою умовою фільтрувати, і отримує її ззовні через делегат Predicate<T>

**2. У чому полягає різниця між Func та Action?**

func приймає параметри і повертає значення (останній тип у Func<T, TResult> це тип результату), а аction приймає параметри, але нічого не повертає (void). Predicate<T> це окремий випадок, який приймає елемент і повертає true або false

**3. Як лямбда-вирази спрощують роботу з делегатами?**

не потрібно писати окремий іменований метод. умову можна записати коротко прямо у виклику, наприклад n => n % 2 == 0, і вона буде видна поруч із кодом, який її використовує

**4. Які переваги дають узагальнені методи при роботі з колекціями?**

код пишеться один раз і працює для будь-якого типу (int, string, Product), без дублювання, і при цьому зберігається типобезпека: помилки типів знаходить компілятор, а приведення типів не потрібні. у моїй лабі CollectionHelper<T>.filter працює і зі списком чисел, і зі списком рядків, і зі списком продуктів
