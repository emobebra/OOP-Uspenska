## Чому делегати корисні для створення таких утиліт?

делегати дозволяють передавати методам різні дії та умови. Завдяки цьому ті самі методи можна використовувати для різних колекцій

## Як лямбда-вирази спрощують виклик цих методів?

лямбда-вирази дозволяють коротко записувати умови й дії без створення окремих методів. Наприклад, n => n * 2 подвоює кожне число

## Порівняйте ваші методи з вбудованими LINQ-операторами

map працює подібно до select, filter до Where, MaxBy до LINQ MaxBy. Метод foreach схожий на List.ForEach. LINQ має більше готових можливостей, а власні методи допомагають зрозуміти принцип їхньої роботи

## Відповіді на контрольні запитання

**1. Чому делегати є зручним механізмом для передавання поведінки в узагальнені методи?**

тому що дозволяють передавати різні функції в один метод без зміни його коду

**2. У чому різниця між Func<T, TResult>, Action<T> та Predicate<T>?**

Func, приймає параметри та повертає результат

Action, виконує дію без повернення результату

Predicate, перевіряє умову та повертає true або false

**3. Які переваги дає поєднання generic-методів і лямбда-виразів під час роботи з колекціями?**

можна використовувати один метод для різних типів даних, а потрібні дії записувати коротко через лямбда-вирази

**4. У яких випадках власні утиліти на кшталт Map чи Filter корисно реалізувати самостійно,
навіть якщо існує LINQ?**

коли потрібно краще зрозуміти роботу колекцій або реалізувати власну логіку обробки даних
