**Виконала: Успенська Емілія**

**Тема**: Життєвий цикл об’єкта та керування ресурсами.

**Мета**: Поглибити розуміння життєвого циклу об’єкта в C#, навчитися працювати з некерованими ресурсами, реалізувати інтерфейс IDisposable та патерн Dispose.

## **Хід роботи**

1. **Створення проєкту**
   - Через термінал створено проєкт у директорії `OOP-Uspenska` з назвою `lab3v3`

   ```
   dotnet new console -o OOP-Uspenska/lab3v3
   ```

2. **Реалізування класу згідно з варіантом**
   - У файлі `Program.cs` реалізовано клас `NetworkStream` згідно з варіантом 3
     Клас реалізує інтерфейс `IDisposable` та має:
     - Приватні поля `_address`, `_isStreamOpen` (для імітації некерованого ресурсу), `_disposed`
     - Публічні властивості `Address`, `IsStreamOpen`
     - Конструктор, що "виділяє ресурс" — встановлює `_isStreamOpen = true` та виводить повідомлення про відкриття потоку
     - Метод `Send(string data)`, що виконує дію, пов'язану з класом
     - Метод `Dispose()` для звільнення ресурсу
     - Деструктор, що викликає `Dispose(false)`
     - Захищений віртуальний метод `Dispose(bool disposing)` для реалізації патерну Dispose

3. **Реалізування патерну Dispose:**
   - Реалізовано повний патерн Dispose: метод `Dispose(bool disposing)` перевіряє прапорець `_disposed`, звільняє керовані ресурси (якщо `disposing == true`) та некерований ресурс (закриває потік) незалежно від значення `disposing`
   - Публічний `Dispose()` викликає `Dispose(true)` та `GC.SuppressFinalize(this)`, щоб запобігти зайвому виклику деструктора
   - Деструктор `~NetworkStream()` викликає `Dispose(false)` на випадок, якщо `Dispose()` не було викликано явно

4. **Демонстрування роботи в методі `Main`:**
   - Створено об'єкт з використанням `using` — `Dispose()` викликається автоматично при виході з блоку
   - Створено об'єкт без `using` з явним викликом `Dispose()`, після чого показано, що повторне звернення до методу `Send()` вже не працює з ресурсом
   - Створено об'єкт без виклику `Dispose()` в окремому методі — після виходу з нього викликано `GC.Collect()` та `GC.WaitForPendingFinalizers()`, щоб продемонструвати роботу деструктора

## **Контрольні запитання**

**1. Що таке життєвий цикл об’єкта в .NET?**

це шлях об'єкта від створення до видалення. спочатку при new виділяється пам'ять у купі (heap) і викликається конструктор. Потім об'єкт використовується через посилання на нього. коли посилань на об'єкт не лишається, збирач сміття (gc) позначає його на видалення. якщо в класі є деструктор, він викликається перед тим, як пам'ять остаточно звільниться (цей етап не обов'язковий)

**2. Яка різниця між керованими та некерованими ресурсами?**

керовані ресурси це звичайна пам'ять .net-об'єктів, її автоматично прибирає збирач сміття, і про це думати не треба. некеровані ресурси це те, що знаходиться поза .net: файлові дескриптори, з'єднання з базою даних, мережеві потоки, бібліотеки, які написані не на .net. gc їх закрити не вміє, тому їх треба звільняти явно, через dispose(). У лабі це імітує _isStreamOpen

**3. Для чого призначений інтерфейс IDisposable?**

це стандартний спосіб сказати, що клас тримає ресурс, який треба звільнити вручну. інтерфейс має один метод dispose(), який закриває ресурс. його можна викликати явно або через using

**4. Як оператор using допомагає в керуванні ресурсами?**

він гарантує, що dispose() буде викликано автоматично, коли програма виходить із блоку using, навіть якщо всередині виникла помилка (виняток). тобто не треба пам'ятати про виклик dispose() самому, і ресурс не залишиться відкритим

**5. Навіщо в патерні Dispose використовується метод GC.SuppressFinalize()?**

коли dispose() уже все закрив, деструктор для цього об'єкта більше не потрібен. GC.SuppressFinalize(this) каже збирачу сміття не викликати деструктор для цього об'єкта. це економить роботу, бо не буде зайвого виклику, і об'єкт видаляється швидше, бо об'єкти з деструкторами живуть довше
**6. Чому в деструкторі викликається Dispose(false), а в методі Dispose() - Dispose(true)?**

параметр disposing показує, хто викликав метод. коли метод викликає dispose() (програміст або using), це true: тоді безпечно звільняти і керовані ресурси, і некеровані. коли метод викликає деструктор, це false: тоді збирач сміття вже міг видалити керовані об'єкти, і звертатись до них небезпечно, тому звільняємо тільки некеровані ресурси
